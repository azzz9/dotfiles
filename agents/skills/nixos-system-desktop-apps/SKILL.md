## When to Use
NixOS のシステム側へのアプリ導入を依頼されたときに使う。Home Manager 側への追加には使わない。

## Procedure
1. 現在の /etc/nixos/configuration.nix とシステムの nixpkgs channel を確認する。要求されたパッケージがその channel にあることを評価し、変更前のシステムとコマンドの参照先を保存する。
2. 変更前に管理者権限を確認する。sudo の非対話認証ができず、KDE の認証画面を使える場合は pkexec による root 実行を確認する。パスワードをチャットで受け取らない。
3. 設定のコピーへ最小変更を加える。通常のアプリは environment.systemPackages に追加する。Steam は programs.steam.enable を使い、必要な32ビット描画環境も評価する。構文、システム評価、dry-run、ビルドの順で確認する。
4. 適用直前に、システム設定とハードウェア設定が作業開始時と一致することを確認する。バックアップを保存してから検証済みの設定を配置する。評価時と同じ channel で nixos-rebuild switch を実行し、稼働中のシステムとバックアップを確認する。
5. デスクトップエントリから各アプリを起動する。実行ファイル、プロセス、対象ウィンドウの画面を照合する。対象外の購入、ゲーム起動、メッセージ送信、通話は行わない。

## Pitfalls
- 安全チェックが root スクリプトの動的なパスを検査できない場合は、その説明に従って検査可能な固定パスの呼び出しへ単純化する。安全チェックを無効化したり、別方式で迂回したりしない。
- Nix の GUI ラッパーはプロセス名が .ghostty-wrappe のように変わる。pgrep -x とパッケージ名の不一致だけで起動失敗と判断しない。
- アクティブウィンドウの撮影は別アプリを写すことがある。撮影対象のタイトルとクラスを確認する。XWayland のアプリでは xdotool を一時的な nix-shell から利用できる。
- スクリーンショットにアカウント情報が写る場合は非公開の作業ディレクトリへ保存する。最終返信や公開レビューへ画像を転載しない。
- 別端末の sudo 認証が、このエージェントの非対話実行へ引き継がれるとは限らない。管理者権限を確認できなければシステムへの適用を完了扱いにしない。

## Verification
1. 配置した設定が検証済みのコピーと一致し、バックアップが元の設定と一致する。
2. nixos-rebuild switch が成功し、稼働中のシステムに要求されたアプリが存在する。
3. 各アプリのコマンドが /run/current-system/sw/bin に存在し、デスクトップエントリも利用できる。
4. 実際の画面が要求したアプリであることを確認する。プロセスの存在だけを起動成功の根拠にしない。
5. 評価、ビルド、適用、画面確認の結果と検証範囲をローカルに記録する。
