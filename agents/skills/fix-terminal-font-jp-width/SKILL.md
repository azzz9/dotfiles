## When to Use
Ghostty などの端末で日本語だけ字間が広い、または狭いと感じたとき。合成フォント (欧文+日本語) の全角送り幅がセル幅の2倍になっていない疑いがあるとき。端末ごとの再スケール挙動はフォント計測だけでは決まらないので、実画面の計測から始める。

## Procedure
1. フォントの hmtx から欧文 ('A' など) の送り幅を読み、それを端末の1セル幅とする。全角グリフ (かな・漢字) の送り幅と 2セル分を比べる。
2. 実画面で字面を測る。同じ文字を N 個と 2N 個並べた行を含むテキストを端末ウィンドウで表示し、スクリーンショットを撮り、行ごとの字面幅と字間を画素で求める。ピッチが送り幅、字面がインク幅になる。
3. 拡大率を決める。目標は参照フォント並みの充填率 (字面 / 2セル箱 = 0.8〜0.9)。factor = 目標字面 / 現在字面。
4. fontTools で全角グリフだけを組み直す。グリフを TransformPen + TTGlyphPen でインク中心基準に拡大し、hmtx の送り幅を2セルに設定する。全角グリフは配布元の jp_width 値 (送り幅) で識別できる。
5. 別 family 名の試作を作り、fonts ディレクトリとは別の場所に置いて fc-cache し、端末の新規ウィンドウで描画を確かめる。primary font の CJK が端末側で再スケールされていないかを、試作と現行の画素比較で判定する (同じなら端末が再スケールしている)。
6. 本採用では family 名を変えずに全ファイルを処理し、元ファイルを fonts ディレクトリ外へ控えてから fc-cache -f する。

## Pitfalls
- fonts ディレクトリの中に元ファイルや試作を置くと family 名が衝突する。控えと試作はディレクトリ外に置く。
- アクティブウィンドウ頼みのスクリーンショットは別のウィンドウを拾う。撮影後に画像サイズを検査して再試行する。
- fontTools で組み直したグリフはヒンティング命令を失う。幾何が変わるので元の命令は使えない。
- 端末の adjust-cell-width では字面と箱の比率は直らない。箱と字面が一緒に動く。
- 端末が CJK をセル幅へ拡大している場合、フォント側の変更は無効。先に試作で確かめる。

## Verification
1. インストール後に同じ撮影手順で再計測し、字面 / 箱 の比が参照フォント並み (0.8〜0.9) になっている。
2. 欧文と日本語を混在表示し、字間と行送りが破綻していない。
3. 既に起動している端末インスタンスでは古いフォントがキャッシュされている。新規インスタンスで確認する。
